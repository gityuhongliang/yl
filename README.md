# yl

区别于提示词推动codex接近需求；yl通过下列特性达成竞赛行为：通过本地代理统一管理 Codex CLI 的上游连接与运行环境，让模型行为评测、护栏有效性验证与受控任务配置在一个图形面板内完成，而非依赖零散的手写提示词文件。


## 特性

- **本地代理**（`127.0.0.1:8080`）：统一接管 Codex CLI 到上游中转站的连接，集中管理环境配置
- **会话指令配置**：以 `bridge.md`（可编辑文本，可自由扩展）设定模型的会话行为约束
- **输出改写规则**：39 条内置正则（可自由编辑扩展）× 中英俄日，用于护栏有效性测试的响应改写验证；规则存于外部 `tamper-rules.txt`，重启代理生效
- **记忆**：评测过程中成功交互的日志沉淀（`memory.json`）
- **技能管理**：28 个可组合任务模块的一键部署/还原/启用/禁用
- **模型管理**：拉取上游可用模型列表，点选即持久化
- **对话页**：面板内直接与 Codex 交互（`codex exec` 多轮会话，可指定工作目录）；代理运行中走评测管道，停止时直连
- **仪表盘**：实时查看交互、类别、耗时与改写标记

## 架构

```
Codex CLI ──:8080──▶ 会话指令(bridge.md) ──▶ 输出改写规则(39条×4语言) ──▶ 记忆 ──▶ 监控
                                                                              │
                                                                              ▼
                                                                          中转站
```

管道按职责划分扩展（指令配置 / 改写规则 / 记忆 / 监控），各扩展互不耦合。

## 使用方法

**环境要求**：Windows 10 / 11（界面使用系统自带 WebView2）。

需自行安装 Node.js 18+ 与 Codex CLI：

```bash
npm install -g @openai/codex
```

安装后先运行一次 Codex CLI，生成 `~/.codex` 目录。

**使用步骤**：

1. 下载本仓库 `yl.exe`，与 `codex-skills/`、`bridge.md` 放在同一目录（建议用户目录，如桌面 / 文档）
2. 双击 `yl.exe` →「配置管理」填入上游地址与 API Key
3. 「获取模型列表」→ 点选模型
4. 「启动代理」：自动备份并改写 `~/.codex/config.toml`，部署 bridge.md 与技能模块
5. 在 Codex CLI 中对话，或直接用内置「对话」页
6. 「停止代理」自动还原配置；异常退出下次启动自动恢复

## 文件说明

```
├── yl.exe                 # 主程序（便携版，免安装）
├── codex-skills/          # 28 个任务模块（需与 exe 同目录）
├── bridge.md              # 会话指令配置（可自行编辑）
├── tamper-rules.txt       # 输出改写规则（可自行编辑）
└── 使用说明.txt            # 完整使用文档
```

> `memory.json`、`logs/` 首次运行后自动生成。

## 为什么需要这类工具（Why）

大语言模型在生产与安全场景的广泛应用，使模型鲁棒性评测（Red-Teaming）成为对齐研究的必要环节：

1. **暴露防御边界**：在受控环境中考察输入逃逸、提示注入与非预期行为，可帮助安全团队定位防护盲区，反哺护栏（Guardrails）与系统安全层建设。
2. **构建可复现基准**：标准化的评测用例集为防御策略提供可量化"标尺"，避免安全建设停留在经验层面。
3. **推动对齐研究**：透明、可复现的评测基线是模型原生安全学术研究的基础设施。
